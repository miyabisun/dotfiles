# 動く構成図をGitHub Pagesで見せる

成果物は、対象repoのGitHub Pagesに置く3つの静的ファイルと、その公開URLである。
`assets/` の `index.html`（小窓のプレイヤー）、`arch.js`（描画と再生操作）、`spec.js`（図の中身）をコピーし、`spec.js` だけを書き換える。
外部への通信とWebフォントは使わないので、file:// でもPagesでも同じに動く。

## 仕組み

`arch.js` は時刻tを受け取り、その瞬間の絵をSVGに描く。乱数や実時間を絵に使わないので、どの時刻へ飛んでも同じ絵になる。

1. ノードが並び順に現れ、両端が出そろった線から引かれる。
2. ステップごとに関係するノードだけを明るくする。札が `flow` の区間を順に流れ、着いたノードが波紋で反応する。そのあと吹き出しの行が上から出る。
3. 締めでは全部の線に粒を流し、消えてから頭に戻る。

字幕（小見出しと1文）は図の下にHTMLで出る。
再生と一時停止はボタンか図のクリック、前後のステップへはボタンで移り、シークバーと全画面ボタンもある。
プレイヤーを選んでいるときは、Spaceで再生・一時停止、←/→で前後のステップへ移る。ページに埋め込んでも、Spaceでのスクロールを奪わない。
`?t=秒` を付けて開くと、その時刻で止まる。動きを減らす設定のブラウザでは自動再生せず、全体が出そろった絵で止める。

## 手順

1. 見る人と、伝えたい1文を決める。技術者向けか専門外の人向けかで、使う言葉が変わる。1文は締めの字幕になる。
2. 実物から中身を取る。コード・設定・実際の実行記録（ログ、入出力）を読み、1文が今の動きと合うか確かめる。
   合わなければ、今の動きで作るかをuserに聞く。吹き出しの数字や例は実物から取り、作り話で埋めない。
3. 公開先を決める。Pagesは誰でも見られるので、秘密・認証情報・個人情報・社外秘の値をspecに書かない。
   実データはそれらを伏せて使う。`gh api repos/<owner>/<repo>/pages` で公開元を調べる。
   - branchから公開している: その公開元のpath（例 `/docs`）の下に `arch/<名前>/` を作る。
   - Actionsで公開している（`build_type: workflow`）: workflowが成果物に含めるディレクトリへ置く。
   - 未設定（404）: `docs/arch/<名前>/` に置き、既定branchの `/docs` を公開元にする。
     `gh api -X POST repos/<owner>/<repo>/pages -f 'source[branch]=<既定branch>' -f 'source[path]=/docs'`
     private repoでPagesを使えないplanなら、そこで止めて報告する。
4. `assets/` の3ファイルをそのディレクトリへコピーし、`spec.js` を書く（下の書式）。
   対象製品のDESIGN.mdに色の決まりがあれば、`index.html` の `:root` の色をそれに合わせる。
   - 文書サイト（GitHub PagesのJekyllなど）の各ページに埋め込むときは、`arch.js` を1つだけ置き、ページごとにspecを読み込む。
     プレイヤーの部品は `index.html` の `<figure class="player">` と `<style>` をサイトのレイアウトへ写す。
     ページの見出しは書き換えない（specのtitleが入るのは `data-spec-title` を付けた要素だけ）。
5. ChromiumとPlaywrightで開いて確かめる。ステップの時刻は、ページで `ARCH.timeline(SPEC)` を評価すると取れる。
   各ステップの終わり1秒前と、札が流れている途中を `?t=` で撮って見る。
   - 線がノードを横切らず、吹き出しがノードや別の吹き出しに重ならない。
   - consoleに `edge not found` などが出ない。
   - 光るノード・流れる区間・吹き出しが字幕の内容と合い、数字や名前が実物と合う。
   - 暗色・明色の両方で読め、幅360pxで横にはみ出さない。
6. commit・pushし、`gh api repos/<owner>/<repo>/pages/builds/latest` のstatusが `built` になるのを待つ。
   公開URLを開いて表示を確かめ、URLをuserに返す。

## specの書き方

`assets/spec.js` は、dotfilesの `bw-secret load` の流れを描いた見本である。上書きする前に書き方を読む。

```js
window.SPEC = {
  title: 'ページの見出し', subtitle: '見出しの下の1文 (無くてよい)',
  grid: [3, 2], // 列数, 行数。既定 [3, 2]
  nodes: [ // 並び順 = 登場順
    { id: 'api', label: '検索API', sub: 'Rust / axum', color: '#3b8fd9', col: 1, row: 0, w: 380 },
  ],
  edges: [{ from: 'api', to: 'db', dashed: true }], // dashed = 常に通るわけではない道
  steps: [{
    kicker: 'SEARCH', caption: '名詞だけで本を探す', // 小見出しと字幕
    flow: [['api', 'db'], ['db', 'api']], // 札が順に流れる区間。線の向きと逆でもよい
    token: '検索語', // 札の名前。無ければ粒だけが流れる
    note: { node: 'db', lines: ['猫, 小説', '10冊に点数'], side: 'above' }, // 吹き出し。side は above/below/left/right
    focus: ['api', 'db'], // 明るくするノード。既定は flow に出るノード
    hop: 0.8, dur: 4, // 1区間の秒、ステップの秒 (既定は出そろって1.6秒後)
  }],
  outro: { kicker: 'DONE', caption: '締めの1文' },
};
```

- `col` と `row` は0始まりで、小数も使える。横に離れたノードは左右の辺を、縦に離れたノードは上下の辺をS字で結ぶ。線が他のノードを横切らない並びにする。
- ノードは4〜8個にする。多ければまとめるか、図を2つに分ける。同じ種類のノードは同じ `color` にする。
- 字幕は1文、30字くらいまでにする。説明ではなく、何が起きたかを書く。
- 札の名前は、運ばれるものが変わるたびに変える（質問 → 検索語 → 結果 → 返事）。
- 吹き出しは2〜4行で、実データの要点だけにする。既定では、図の上半分のノードなら下に、下半分なら上に出る。重なるときは `side` で左右や上下に変える。
- 専門外の人向けなら、ファイル名・関数名・JSONの形を出さず、中身を表す言葉で書く。
