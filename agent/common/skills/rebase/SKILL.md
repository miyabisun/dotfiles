# rebase

**feature branch は常に既定ブランチの先端に載っている。** それが正常な状態である。
遅れているのを**見つけたら、その場で機械的に載せ直す**。予定に入れる話でも、
号令を待つ話でもない。見つけた者がやる。

これは衛生作業であって配達ではない。**clean に通ったらそれで完了である** —
テストもレビューも走らない。既定ブランチは触らない。

## 起動条件

- **遅れを見つけたとき**: 号令は要らない。その feature branch を載せ直す
- **user が `$rebase` を起動したとき**: 名指しされた repository と feature branch を載せ直す
- **`merge` から持ち替えて来たとき**: feature を載せ直して push したら、**`merge` へ戻る**。
  rebase 自身は統合まで進まない

いずれの経路でも触るのは **feature branch だけ**である。

## 手順

1. **origin を最新化し、既定ブランチを解決する**: `git fetch` で origin を最新にし、
   **remote HEAD から既定ブランチ名を解決する**。`main` と決め打ちしない —
   `git symbolic-ref refs/remotes/origin/HEAD` や `git remote show origin` の
   HEAD 表示など、remote が申告する値を使う。解決できなければ推測せず、
   その旨を報告して止まる。既に `origin/<default>` の先端に載っているなら何もしない。
2. **feature の上で rebase する**: feature branch で `git rebase origin/<default>`。
   merge commit で被せない。
3. **通ったら push して完了**: 書き換わった feature branch を
   `git push --force-with-lease` で push する (履歴が変わるので force なし push は
   できない)。**ここで終わりである。テストもレビューも行わない。**
   並行更新で `--force-with-lease` が拒否されたら**手順 1 からやり直す**。
   `--force` で押し通さない。
4. **コンフリクトが出たときだけ解消する**: 解消したら、**影響する実行可能コードの
   既存テストを回す** (repo 標準のもの。存在しないチェックを新設しない)。
   変更が Markdown・設定・docs だけならテストは要求しない。
   既存の有効なテストを、通すために改変・削除しない。解消できたら手順 3 へ進む。
5. **報告する**: 解決した既定ブランチ名、rebase の結果、解消したコンフリクトと
   その分類 (機械的 / 製品判断)、回したテスト、push の対象を短く返す。

## 製品判断の境界

コンフリクトには 2 種類ある。

- **機械的な衝突はその場で吸収してよい**: import 順、行の重複、隣接行の並び、
  生成物の再生成、両方を残せば足りる追加同士 — どちらを採っても製品の
  振る舞いが変わらないもの。
- **2 つの機能が本当に両立せず、どちらを採るかが製品判断になる衝突は user へ返す。**
  **agent が勝手に片方を採用しない。** `git rebase --abort` で feature を
  着手前の姿へ戻し、衝突した 2 つが何をしようとしていたか、両立しない理由、
  選択肢とそれぞれの帰結を receipt に書く。

判定は「どちらを選んでも user から見える結果が同じか」で行う。同じなら機械的、
変わるなら製品判断である。迷ったら製品判断として扱い、user へ返す。

## 不変条件

- 触るのは **feature branch だけ**。既定ブランチへ push しない — 統合は `merge` の仕事
- **clean に通ったらそれで完了。** テスト・レビューを push の条件に足さない
- push は `--force-with-lease`。拒否されたら最新からやり直す。`--force` で上書きしない
- 既定ブランチ名を決め打ちしない。remote HEAD から解決する
- 既存の有効なテストを、通すために改変・削除しない
- **製品判断になる衝突は user へ返す。** 勝手に片方を採用しない
- `merge` から来たなら、push のあと `merge` へ戻る
- 破壊的 git 操作で他人の作業を巻き込まない。無関係な作業中変更を保護する
