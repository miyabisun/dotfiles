# Ponytail の実装方針

Ponytail full の簡素化方針を polish / refactor で共有する。
外部 plugin の有無に依存せず、この文書を実装判断の参照先にする。

対象の処理経路・呼び出し元・既存の検証を理解してから、次の順で最初に要件を満たす方法を採る。

1. その機構は必要か。利用者のいない機能や将来だけの備えは削除・省略する。
2. 同じ責務を持つ既存実装を再利用できるか。
3. 標準ライブラリ、プラットフォーム標準機能、導入済み依存の順で代替できるか。
4. それでも必要な部分だけ、最小のコードで実装する。

不具合は全呼び出し元が通る原因箇所で直す。短い差分のために症状だけを塞がない。
不要な中間構造体・転記・設定・独自基盤を減らす。将来の拡張だけのために抽象や設定を足さない。
行数削減を目的に責務を混ぜたり、読みやすさを失わせたりしない。

入力検証、データ損失を防ぐエラー処理、必要なセキュリティ、アクセシビリティ、明示要件は削らない。
実際の上限を承知で簡略化する場合だけ、`ponytail:` コメントに上限と見直す条件を残す。
検証・レビュー・報告は共通契約と project のテスト戦略に従い、簡素化を理由に省略しない。
