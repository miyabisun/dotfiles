# UI/UXとPonytailの適用境界

この境界は要求整理から設計・実装・検証・レビューまで共通とする。
ファイル名や言語ではなく、今決める挙動が利用者に与える影響で対象を分ける。

- Web/nativeのUI、操作、配置、文言、初期値、失敗からの復帰を扱う工程では、
  `stop ponytail`（normal mode）として、継続中のPonytailを明示的に解除する。
  新しく呼ばないだけ、fullをliteへ変えるだけでは解除にならない。
  UIの実装・レビューにもPonytailとponytail-reviewを自動適用しない。
- backendや純粋処理の実現方法には、導入済みの公式Ponytailのskillを読んで使う。
  設計・実装はfull、仕様候補の最小性確認はultra、差分確認はponytail-reviewとする。
  UIと混在する依頼では適用をこの範囲へ限定し、UIへ戻るたびに解除する。
  UIと切り離せない判断はUIとして扱う。依頼全体へ一括適用しない。
- UIでは利用者が読む量、入力・選択・確認の回数、目的達成と復旧の手間を優先する。
  コード量・ファイル数・削減行数を理由に、必要な挙動や合意したUXを削らない。
  必要な挙動を満たした上で、既存componentと標準機能を再利用する。
  操作削減が誤操作・データ損失を招く場合は、必要な確認・入力検証を保つ。

UIの具体的な設計・実測・照合は既存のdesign-context、ui-flow、ui-layout、
platform別skill、ui-reviewが所有する。外部pluginの本文を改造・複製しない。
