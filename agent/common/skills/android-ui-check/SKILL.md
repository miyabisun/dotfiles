# Android画面と起動経路を実測する

入力は要求、製品DESIGN.mdの適用節、差分、代表機器/データ、対象SDKと検証戦略。
対象repoのGradle・instrumentation・既存fakeを使い、接続先serialを毎回明示する。

1. emulatorで実際の部品を操作し、画面全体の画像と結果を確認する。新規画面は
   OS明暗、文字拡大、実利用に近い複数項目・長い名前・空/失敗と主操作を通す。
   部分変更では関連する条件だけを測る。レイアウトは主情報の面積・見える件数・到達性も比較する。
2. 通知・NFC等の入口を変更したら、別アプリ使用中の表示、権限の許可/拒否、
   反復、状態変化の有無、処理の寿命を観測する。受理ログだけで表示維持や完了を断定しない。
3. Bluetooth/NFC/音声など物理境界が必要な結果は、実端末の対象版で確認する。
   fake成功を実タグ・実接続・音の成功に置き換えない。利用者操作が必要なら結果を尋ね、
   依存しない開発を続ける。端末待ちで完了済み開発を戻さず、実機の残件を引き継ぐ。
4. 前面アプリを確認してから必要な画像やUIを取得し、無関係な個人画面/ログを保存しない。
   権限拒否・失敗からの復帰を確認し、試験のために利用者データを消さない。

出力は版/端末/操作と条件ごとの画像・観測結果。mock/emulator/実機、確認済み/失敗/未確認を分ける。
[ui-review](../ui-review/SKILL.md)へ渡し、実装の未達は担当が直して再確認する。
