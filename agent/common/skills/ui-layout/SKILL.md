# 内容と操作を配置する

入力は元の要求、実際の代表データ、既存画面、design-contextで解決した正本。
未解決なら [design-context](../design-context/SKILL.md)を読む。操作が未確定なら [ui-flow](../ui-flow/SKILL.md)へ渡す。

1. 最初の画面に見せる内容と主操作を定める。利用者が探す機器・項目を説明文より先に置く。
   実データに近い件数、長い名前、許可済み/未許可などの混在で配置を決める。
2. 近い情報を一まとまりにし、文字の役割、余白、部品の強さで階層を示す。
   現在地・選択・件数を別の帯へ繰り返さない。説明・詳細・補助操作は必要な場面から開く。
3. 共通原本と製品の部品を再利用する。必要な対比は面の濃淡・境界で作り、
   無関係な装飾や強い面を増やして内容の面積を奪わない。
4. 狭い画面、文字拡大、空・失敗状態で主操作まで到達できるかを設計する。
   Webはページの縦スクロール、Androidはnativeのスクロールとsystem insetを基準にする。

出力は製品DESIGN.mdの配置・部品・文字・寸法と、変更前後に観測する件数/面積/到達性。
「見やすくする」だけを成果にしない。用途に必要な密度と操作領域を具体化したら、
[frontend-design](../frontend-design/SKILL.md) または [android-ui](../android-ui/SKILL.md)へ渡す。
色の値とテーマは [ui-theme](../ui-theme/SKILL.md)が所有する。
