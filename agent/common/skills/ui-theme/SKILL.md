# 製品のテーマを適用する

入力は元の要求、製品の色/tokenと設定、design-contextで解決した原本。
未解決なら [design-context](../design-context/SKILL.md)を読む。原本のColorsとテーマ状態を実際に確認する。

1. 新規UIは共通原本の暗色から設計し、通常の明色も用意する。既存製品は採用済みの
   契約と変更要求を照合し、色値を想像で補ったり文書整理だけでテーマを変えたりしない。
2. 背景・面・文字・補助文字・境界・アクセント・失敗の意味を製品tokenへ対応付ける。
   値の定義を製品の一箇所に集約し、画面内の色直書きへ分散させない。
   原本のアクセント面積と用途を守り、選択・focus・データ分類を混同しない。
3. OSへの追従、既存の手動選択と保存、初回描画、再生成の動作を製品に合わせて定める。
   AndroidへWebのlocalStorageやテーマメニューを機械的に移植しない。
4. 明暗両方で文字・主操作・無効状態を確認する条件を定める。色だけで意味を伝えず、
   原本のコントラスト基準とplatformのaccessibilityを満たす。

出力は製品DESIGN.mdの両テーマの値/用途/状態仕様と、実装側のtokenの対応。
[frontend-design](../frontend-design/SKILL.md) または [android-ui](../android-ui/SKILL.md)へ渡し、
対応する画面実測でOS切替も含めて確認する。設計だけで適用済みにはしない。
